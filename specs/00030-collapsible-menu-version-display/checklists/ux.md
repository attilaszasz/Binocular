# Checklist: UX — Collapsible Menu & Version Display

- [X] CHK001 Are tooltip appearance delays differentiated for mouse hover (200-300ms) vs keyboard focus (immediate)? [Clarity, Spec §FR-003, STF-002]
- [X] CHK002 Is the tooltip dismissal trigger specified (immediate on mouse leave or blur, no auto-dismiss timeout while hovering)? [Completeness, Spec §FR-003, Q003]
- [X] CHK003 Does FR-003 require aria-label on every collapsed NavLink element for screen reader support? [Completeness, Spec §FR-003, Research §WCAG SC 4.1.2]
- [X] CHK004 Is the tooltip ARIA relationship (role="tooltip" on container, aria-describedby on trigger) specified? [Completeness, Research §ARIA APG Tooltip]
- [X] CHK005 Are visible focus indicators required for all focusable sidebar elements (toggle button, nav links) in both collapsed and expanded states? [Accessibility, Research §WCAG SC 2.4.7]
- [X] CHK006 Is the DOM focus order specified so the toggle button (sidebar bottom) appears after nav items in the DOM? [Accessibility, Research §WCAG SC 2.4.3]
- [X] CHK007 Is the sidebar required to carry an ARIA landmark role (e.g., navigation or complementary) for screen reader skip-nav? [Completeness, Research §WCAG SC 2.4.1]
- [X] CHK008 Are Escape key dismissal and "focus stays on trigger" behavior specified for nav-item tooltips? [Completeness, Research §ARIA APG Tooltip]
- [X] CHK009 Are minimum contrast ratios specified for version text and tooltip text (AA 4.5:1) in both dark and light modes? [Accessibility, Research §Dark/Light, Research §WCAG SC 1.4.3]
- [X] CHK010 Is non-text contrast (WCAG SC 1.4.11, 3:1 minimum) specified for the toggle icon and focus rings? [Accessibility, Research §Dark/Light, Research §WCAG SC 1.4.11]
- [X] CHK011 Does FR-008 explicitly require using existing --color-* CSS custom property tokens (not raw hex) for all new UI elements? [Consistency, Spec §FR-008]
- [X] CHK012 Is the orthogonality requirement stated — theme mode switching must NOT change sidebar collapse state? [Clarity, Spec §Edge Cases, Research §Dark/Light]
- [X] CHK013 Are tooltip background and text colors required to use theme tokens for dark/light compatibility? [Completeness, Spec §FR-008, Research §Dark/Light]
- [X] CHK014 Are there testable success criteria for verifying correct rendering of toggle and version display in both light and dark modes? [Testability, Spec §SC-006]
- [X] CHK015 Is the localStorage key name (binocular-nav-collapsed) specified and unique enough to avoid collision with other features? [Clarity, Spec §FR-006]
- [X] CHK016 Are both read-failure and write-failure error handling mechanisms (try-catch, default to expanded) fully specified? [Completeness, Spec §FR-006, STF-003]
- [X] CHK017 Is the default sidebar state (expanded) clearly defined when no localStorage value exists or storage is unavailable? [Clarity, Spec §FR-006, §Edge Cases]
- [X] CHK018 Is the cross-tab synchronization behavior (last-write-wins, no storage event listener) documented as an accepted limitation? [Completeness, Spec §FR-006, STF-005]
- [X] CHK019 Does the spec address localStorage SecurityError scenarios (private browsing, file:// origin, blocked cookies)? [Completeness, Research §localStorage, Spec §FR-006]
- [X] CHK020 Is the in-memory state behaviour on write failure described (collapsed for current session, persistence lost silently)? [Completeness, Spec §FR-006, Research §localStorage]
- [X] CHK021 Is the icon convention specified unambiguously (PanelLeftClose when expanded, PanelLeftOpen when collapsed)? [Clarity, Spec §FR-001, Q001]
- [X] CHK022 Is the aria-expanded attribute semantics specified correctly (true when sidebar IS expanded, false when collapsed)? [Clarity, Research §ARIA APG Disclosure, HINT-004]
- [X] CHK023 Are distinct aria-label values specified for the toggle button in each state ("Collapse sidebar" / "Expand sidebar")? [Accessibility, Research §WCAG SC 4.1.2]
- [X] CHK024 Is keyboard activation (Enter/Space) specified for the toggle via native <button> semantics? [Completeness, Spec §FR-001, Research §Toggle]
- [X] CHK025 Is rapid-click/debounce protection specified to prevent animation or layout glitches from repeated toggles? [Usability, Spec §Edge Cases]
- [X] CHK026 Is the toggle button position specified relative to other sidebar elements (bottom, above version string, outside scrollable <nav>)? [Clarity, Spec §FR-001, FR-004]
- [X] CHK027 Are all eight functional requirements (FR-001–FR-008) traceable to at least one user story or success criterion? [Traceability, Spec §Requirements, §Success Criteria]
- [X] CHK028 Are the collapsed/expanded width values (md:w-16 / md:w-64) defined consistently across FR-001, SC-001, and the Key Entities? [Consistency, Spec §FR-001, SC-001]
- [X] CHK029 Is the viewport breakpoint for collapsible behavior (≥768px, md:) applied consistently in all requirements and success criteria? [Consistency, Spec §FR-001, SC-001, STF-001]
- [X] CHK030 Is the version abbreviation strategy completely defined for all three version types (SemVer tag, SHA fallback, "dev" fallback)? [Completeness, Spec §FR-004, STF-004]
- [X] CHK031 Is the version tooltip in collapsed state required (SHOULD/MAY/MUST) and consistent with nav-item tooltip behaviour? [Clarity, Spec §FR-004, SC-003]
- [X] CHK032 Is the main content margin-left transition specified to synchronise exactly with sidebar width transition (md:ml-64 ↔ md:ml-16)? [Consistency, Spec §FR-001, Q009]
- [X] CHK033 Does the spec require deep-linking to work identically in both collapsed and expanded states? [Completeness, Spec §Edge Cases, FR-007]
- [X] CHK034 Are all acceptance scenarios independently testable without relying on implementation details? [Testability, Spec §User Scenarios]
- [X] CHK035 Is the version display positioning (sticky bottom, outside scrollable <nav>) specified consistently across FR-004 and the Key Entities? [Clarity, Spec §FR-004, Q005]
