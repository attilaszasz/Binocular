# Epic Details: E027 — Source-Aware HTTP Pacing

- **Category**: TECHNICAL
- **Priority**: P1
- **Source**: {PRD:CAP-008}{SAD:ADR-0012}

## Scope
Extend the centralized `ScrapeClient` to honor valid applicable source crawl delays through one shared normalized-origin pacing timeline across concurrent checks and every retry. Make multi-request execution automatically source-aware but finite, preserve default pacing and budgets for unaffected origins, and guarantee timeout or cancellation cannot leave requests running in the background.

## Traceability & Dependencies
- **Actors**: None (internal); module authors consume the existing client contract
- **Key Entities**: ScrapeClient, OriginPacingState, CheckDeadline
- **Depends on**: E005 (ScrapeClient), E007 (module timeout boundary), E012 (manual and bulk checks), E013 (scheduled checks)
- **Dependency Contracts**: E005 provides centralized robots/User-Agent/backoff enforcement; E007 provides the module invocation boundary; E012 and E013 provide concurrent check callers
- **Depended on by**: None
- **Produces (shared)**: Source-aware origin pacing and bounded cancellation semantics for ScrapeClient
- **Constraints**: Preserve RFC 9309 allow/disallow enforcement and identifiable User-Agent; treat `Crawl-delay` as a non-standard hint; no required user configuration; every network attempt re-enters pacing; bounded end-to-end execution; unaffected origins retain existing pacing and budgets

## Acceptance Criteria
- [ ] Effective pacing selects the greater of the conservative default and a valid applicable source `Crawl-delay`; missing, invalid, or shorter declarations leave default pacing unchanged, with state isolated by normalized origin.
- [ ] Concurrent same-origin checks, robots retrieval, redirects, and every retry use one atomically coordinated pacing/cooldown timeline while cross-origin checks remain independent and existing robots, User-Agent, and exponential-backoff behavior is preserved.
- [ ] Multi-request checks receive automatic finite budget accommodation only when a longer effective source delay requires it; timeout or cancellation covers queueing, pacing, backoff, and I/O, propagates cleanly, and prevents subsequent background requests.
- [ ] Deterministic tests use injected monotonic timing and scripted transports to cover delay selection, pacing, retries, concurrency, cross-origin independence, preserved default budgets, bounded execution, timeout, and cancellation without real sleeps or live requests.

## Specify Input
- **Description**: Extend the centralized HTTP client with automatic source-declared crawl-delay selection, shared per-origin pacing across concurrent checks and every retry, source-aware finite execution budgets, and cancellation that prevents post-timeout background requests while preserving existing behavior for unaffected sources.
- **Actors**: Module authors indirectly through the host-provided client; operators require no configuration
- **Key Entities**: ScrapeClient, OriginPacingState, CheckDeadline
- **Depends on Artifacts**: E005 ScrapeClient, E007 module invocation boundary, E012 manual/bulk checks, E013 scheduled checks, ADR-0012
- **Constraints**: Preserve robots enforcement, identifiable User-Agent, and exponential backoff; effective delay never below the default; no required user configuration; every retry is paced; source-aware accommodation is capped; unaffected execution budgets remain unchanged; timeout/cancellation leaves no outbound background work
