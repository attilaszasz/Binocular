# Epic Details: E034 — Inventory-Independent Catalog Refresh

- **Category**: PRODUCT
- **Priority**: P1
- **Source**: {PRD:CAP-004}{PRD:CAP-005}{PRD:CAP-008}{PRD:CAP-016}{SAD:ADR-0012}{SAD:ADR-0015}{SAD:ADR-0017}{DOD:DDR-005}

## Scope
Refresh active catalog-capable modules independently of ownership, persist model/firmware results, and serve bounded local catalog queries/status. Demonstrate the working increment with fixture-backed V2 modules; real official-source migration belongs to E035, and draining shared comparison/delivery work belongs to E036.

## Traceability & Dependencies
- **Actors**: Operator, scheduler
- **Key Entities**: CatalogModel, FirmwareObservation, CatalogRefreshRun, source mapping, module controls/capability, ReevaluationWork
- **Depends on**: E032, E033, E012, E013, E027
- **Dependency Contracts**: E032 atomic persistence, exact identity resolution and durable-work primitives; E033 negotiated V2/V1 and shared refresh context; existing single/bulk checks and centralized robots/pacing/backoff/deadline/cancellation
- **Depended on by**: E035, E036, E037, E038, E039
- **Produces (shared)**: Inventory-independent scheduler/coalescing refresh service; durable run/progress/cursor lifecycle; successful observation plus reevaluation enqueue; DB-only model list/detail APIs; explicit 202 refresh/status APIs and source/capability/status response shapes
- **Constraints**: No inventory-derived enumeration or repeated discovery per physical copy. Module-wide frequency/pause preserved, explicit manual refresh allowed while paused. All source work is bounded/polite; passive local GETs never run modules. Firmware observation age and endpoint-discovery TTL are separate.

## Acceptance Criteria
- [ ] Every active unpaused catalog-capable module schedules enumeration/firmware refresh even with zero devices. Saved module-wide frequency/pause survive restart/update; missed windows coalesce, successful manual refresh while paused retains normal freshness/comparison eligibility, and legacy V1 keeps its labeled owned-device checks without fabricated enumeration.
- [ ] Manual module/model and existing single/bulk inventory checks enqueue/coalesce background work by unique compatible model, reuse shared index responses where possible, consume valid inline firmware or request per-model details, and issue no duplicate manufacturer discovery per owned copy. Deterministic request-count tests cover shared-index and multi-detail sources plus overlapping scheduled/manual requests.
- [ ] Finite fair batches, per-model deadlines, run budgets, generations/leases, and resumable cursors preserve partial progress across restart. Cancellation/timeout stops further outbound requests, exhausted work terminates visibly partial/failed, and a slow source cannot silently starve other modules. No network I/O holds a SQLite write transaction.
- [ ] Successful matching authoritative results atomically persist observations plus reevaluation work; exact unambiguous legacy linking uses E032 resolution without guessing. Enumeration success is separate from firmware success; failed/unverified portions retain original verification times while successful models in partial runs advance their own times, and only complete authoritative absence marks models missing. Freshness is age below module interval (default daily); endpoint mappings retain strict below-24-hour expiry/invalidation and one full-discovery recovery.
- [ ] GET /api/v1/modules/{id}/models and /{model_id} perform local name/alias search and stable-ID lookup with default 50/max 100 results, deterministic cursors, inventory counts, source guidance/links, freshness/attempt/completeness/legacy state. Explicit POST /api/v1/modules/{id}/catalog-refresh returns 202 plus run identity and GET /api/v1/catalog-refreshes/{run_id} exposes bounded progress/errors. A 10,000-model fixture proves bounded reads and zero manufacturer calls from search/detail/status reads, including empty/stale/failed states.

## Specify Input
- **Description**: Separate manufacturer discovery from inventory checking by periodically refreshing every active catalog-capable module, including zero-owned-device sources. Honor module-wide frequency/pause and explicit manual refresh, sharing indexes and per-compatible-model work across scheduled and single/bulk requests. Persist stable models, matching verified firmware observations and durable reevaluation work with honest partial/failure/freshness state, bounded fair resumable jobs, and centralized responsible HTTP. Expose one paged DB-only catalog API for both onboarding entry points plus explicit background refresh/retry and local status; ordinary browsing/typing/selection must never trigger manufacturers.
- **Actors**: Operator, scheduler
- **Key Entities**: CatalogModel, FirmwareObservation, CatalogRefreshRun, ModuleContractDescriptor, SourceEndpointMapping, ReevaluationWork
- **Depends on Artifacts**: E032 repositories/unit-of-work/work primitives, E033 V2/V1 contracts/context, E012/E013 check/schedule controls, E027 client enforcement; ADR-0015/0017 and DDR-005 lifecycle constraints
- **Constraints**: Local SQLite only, per-module controls, no V1 enumeration claim, no new current/alert claim from stale/failed data, strict endpoint TTL separate from observation age, max100 model pages, bounded source work and no requests after cancellation.

## Pipeline Hints
- Validate a deterministic V2 fixture source with zero inventory before official-source migration; freeze API/run contracts for downstream consumers.
