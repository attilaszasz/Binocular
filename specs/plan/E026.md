# Epic Details: E026 — Official Nikon Z-Series Module

- **Category**: PRODUCT
- **Priority**: P2
- **Source**: {PRD:CAP-011}{SAD:ADR-0005}

## Scope
Ship a new official starter module `nikon_z_series` for Nikon Z-Series camera firmware detection. Nikon's Download Center exposes a two-step flow: an XML catalog at `https://downloadcenter.nikonimglib.com/en/0/product_data.xml` listing every product in a `<category layer="main">` → `<category layer="sub">` → `<product>` tree; the module selects `Mirrorless Cameras` / `Z Series` (14 bodies: Z 30, Z 5, Z 50, Z 6, Z 6II, Z 7, Z 7II, Z 8, Z 9, Z f, Z fc, Z50II, Z5II, Z6III), resolves the configured model against the subcategory, then fetches the matched product's relative `href` page and parses the `<div id="firmware" class="contentsType">` → `<div class="pseudoTable">` first row. The version cell carries a `<token>:Ver.<version>` prefix (`C:Ver.` for cameras) which the stripper removes in a class-agnostic way. The module must follow the existing authoring contract (ADR-0005) and pass fixture-based correctness validation.

## Problem Statement
Photographers using Nikon Z-Series mirrorless cameras have no native way to monitor firmware updates through Binocular. The application ships official starter modules for several other manufacturers (Sony Alpha, Panasonic Lumix MFT, Panasonic Lumix Lenses, Godox Flashes, Viltrox Lenses) and the CAP-011 capability covers the shipped-official-modules surface, but Nikon Z-Series support is missing. Operators must currently hand-author a Nikon module against the XML-catalog → per-product-page flow, which fragments the value of an otherwise plug-and-play starter set.

## Demo Plan
- Run the dev environment with the `nikon_z_series` module seeded automatically on startup.
- From the inventory page, create a device linked to the `nikon_z_series` module using model `Z 30`.
- Trigger a manual on-demand check; observe the detected `latest_version` matches the fixture's golden value `1.20` (released `2025-05-07`, download page `https://downloadcenter.nikonimglib.com/en/download/fw/556.html`).
- Update the stored version to an older value (e.g. `1.10`) and re-check; observe a newer-version detection and a notification.
- Run the Playwright end-to-end smoke test and the module's pytest fixture suite against a captured `product_data.xml` catalog + a captured `Z_30.html` product page to confirm zero false positives / zero false negatives.

## Draft Scenarios / Objectives
- **S1 — Module discovery and auto-seeding**: On application startup, the seeder discovers `nikon_z_series.py` in `official_modules/`, validates it (Phase 1 AST + Phase 2 runtime), and upserts the module record in SQLite without duplicating on re-runs.
- **S2 — Two-step flow (XML catalog → product page)**: For a configured model, the module fetches `https://downloadcenter.nikonimglib.com/en/0/product_data.xml` via the host-provided ScrapeClient, parses it with stdlib `xml.etree.ElementTree`, selects `Mirrorless Cameras` / `Z Series`, resolves the configured model via alias-set intersection, then fetches the matched product's relative `href` page and parses the `#firmware` pseudoTable.
- **S3 — Firmware-row extraction with prefix strip**: From the first `<div class="row">` in the `#firmware` pseudoTable, the module extracts the `version` cell (`<token>:Ver.<version>`), strips the class-agnostic `<token>:Ver.` prefix (e.g. `C:Ver.1.20` → `1.20`), normalizes the `YYYY/MM/DD` date to `YYYY-MM-DD`, resolves the relative `View download page` link against the download-center base, and returns the contract-shaped dict.
- **S4 — Model-key normalization**: The module accepts any of `Z 30`, `Z30`, `Z_30`, `z 30`, `z30`, `z_30` (and Roman-numeral variants `Z 6II`/`Z6II`/`Z_6II`/`Z 6 II`) and resolves them all to the same Z Series product via the alias-set intersection rule (uppercase, strip `Z`-prefix whitespace variants, remove `_` and spaces, compare against normalized forms of each `<product name>`).
- **S5 — Honest failure**: Page-structure changes, missing subcategory, unlisted model, missing firmware section, or network errors produce a visible "scrape failed" status with a descriptive standardized error code (`network_error`, `firmware_index_not_found`, `product_not_found`, `firmware_not_available`, `download_url_not_found`), never a silent miss. The prefix `parse_error` is NOT used — structural breakage maps to `firmware_index_not_found` (catalog) or `firmware_not_available` (firmware table), matching the Sony/Panasonic conventions.
- **S6 — Class-agnostic prefix stripping**: The version stripper strips any `<token>:Ver.` prefix (so a future `A:Ver.`/`L:Ver.` lens/accessory prefix is also stripped if encountered), keeping the camera-specific `C:Ver.` the primary case without hard-failing on a different device-class token.

## Integration Points
- **Module engine (E007)**: Implements `check_firmware(url, model, http_client)`, declares `MODULE_VERSION` and `SUPPORTED_DEVICE_TYPE = "camera"`.
- **ScrapeClient (E005)**: All outbound HTTP (XML catalog fetch AND product-page fetch) goes through the host-provided polite httpx client (robots.txt, identifiable User-Agent, rate limiting, backoff). No direct outbound requests.
- **Module seeder (E016)**: The seeder auto-discovers `nikon_z_series.py` in `official_modules/` on startup and upserts it into the modules table alongside the existing official modules.
- **Notification flow (E014)**: When a newer version than the user's recorded version is detected, the same Apprise dispatch path delivers an HTML Email/SMTP and/or Gotify alert. Deduplication via `last_notified_version` still applies.
- **Activity log (E015)**: Successful and failed check events for Nikon Z-Series devices land in the in-UI activity log just like any other module.
- **Official module health monitoring (E020)**: A Nikon Z-Series device whose checks consistently fail will surface in the in-app "official module failing" notification alongside other official modules.
- **Version search on creation (E023)**: When the operator uses the on-demand "search version" button while creating a Nikon Z-Series device, the existing `/api/v1/checks/search-version` endpoint delegates to the module runner with the new module.

## Implementation Signals
- New file: `backend/src/binocular/official_modules/nikon_z_series.py`
- Constants: `MODULE_VERSION = "1.0.0"`, `SUPPORTED_DEVICE_TYPE = "camera"`
- Default URL: `https://downloadcenter.nikonimglib.com/en/0/product_data.xml` (the catalog XML; the per-product page URL is derived from the catalog, NOT passed by the user)
- Entry point: `check_firmware(url: str, model: str, http_client: Any) -> dict[str, Any]`
- Returned dict shape (matching the existing official modules):
  - `latest_version` (str, required) — first firmware row's version with the `<token>:Ver.` prefix stripped (e.g. `1.20`)
  - `release_date` (str | None) — `YYYY-MM-DD` normalized from the row's `YYYY/MM/DD` date (e.g. `2025-05-07`)
  - `download_url` (str) — absolute URL resolved from the row's relative `View download page` link against the download-center base (e.g. `https://downloadcenter.nikonimglib.com/en/download/fw/556.html`)
  - `product_name` (str) — e.g. `Nikon Z 30`
  - `product_model` (str) — the matched Z Series product display name (e.g. `Z 30`)
  - `product_type` (str) — `"Camera"`
- Parse strategy: stdlib `xml.etree.ElementTree` for the XML catalog (select `Mirrorless Cameras` / `Z Series`, collect `<product name>` + `href`); alias-set intersection for model resolution (uppercase, strip `Z`-prefix whitespace variants, remove `_` and spaces, compare against normalized forms of each `<product name>`); regex on the product page's `<div id="firmware" class="contentsType">` → `<div class="pseudoTable">` rows (same idiom as `panasonic_lumix.py`'s `_ROW_RE`/`_CELL_RE`) — first row is latest; class-agnostic `<token>:Ver.` prefix strip on the version cell; `YYYY/MM/DD` → `YYYY-MM-DD` date normalization; relative link resolution against the download-center base.
- Error codes: `network_error`, `firmware_index_not_found`, `product_not_found`, `firmware_not_available`, `download_url_not_found` (NOT `parse_error`).
- Fixture tests: at minimum one captured `product_data.xml` catalog fixture and one captured `Z_30.html` product-page fixture; pytest cases verify the golden happy path (`latest_version = "1.20"`, `release_date = "2025-05-07"`, `download_url = "https://downloadcenter.nikonimglib.com/en/download/fw/556.html"`), model normalization across all input forms, and each failure path.
- `mypy --strict` clean; Ruff clean; follows the same `asyncio.new_event_loop` pattern as the existing official modules for parity.

## Assumptions & Risks
- **Assumption**: Nikon continues to host `https://downloadcenter.nikonimglib.com/en/0/product_data.xml` with the `<category layer="main">` → `<category layer="sub">` → `<product>` tree and the `Mirrorless Cameras` / `Z Series` subcategory names remain stable.
- **Assumption**: Each Z Series product page contains a `<div id="firmware" class="contentsType">` section with a `<div class="pseudoTable">` whose first row is the latest firmware release in the `<token>:Ver.<version>` / `YYYY/MM/DD` / `View download page` shape.
- **Assumption**: The `Z Series` subcategory name in the XML is `Z Series` (not `Z- Series`); the operator-facing wording `Z- Series` refers to the same subcategory.
- **Risk**: Nikon catalog structure changes (e.g. `Z Series` renamed, category tree restructured, `href` attributes removed) — mitigated by per-invocation error boundary (E007) and `firmware_index_not_found` surfacing, plus the official module health monitor (E020) for repeated failures.
- **Risk**: Firmware table layout changes (e.g. `pseudoTable` class dropped, `#firmware` section renamed) — mitigated by fixture-based coverage and `firmware_not_available` / `firmware_index_not_found` surfacing rather than silent skips.
- **Risk**: A Z Series body page exists but has no firmware updates — the module must report `firmware_not_available` rather than guess.
- **Risk**: Responsible-scraping posture (Project Instructions §II) is mandatory — the module must use the host-provided ScrapeClient for BOTH the XML catalog fetch and the product-page fetch and avoid high-frequency polling; the per-module default check interval applies.

## Glossary
- **Nikon Z-Series module**: The new official `nikon_z_series` module shipped under `backend/src/binocular/official_modules/`. Its `SUPPORTED_DEVICE_TYPE` is `camera` and its model key is the Z Series body display name (e.g. `Z 30`).
- **`product_data.xml`**: The Nikon Download Center catalog at `https://downloadcenter.nikonimglib.com/en/0/product_data.xml`, a tree of `<category layer="main">` → `<category layer="sub">` → `<product name="..." href="..." rss="..."/>`. The module selects `Mirrorless Cameras` / `Z Series` and collects the 14 Z Series products.
- **Z Series subcategory**: The `<category layer="sub">` named `Z Series` under the `Mirrorless Cameras` main category. Lists the 14 Z Series bodies: Z 30, Z 5, Z 50, Z 6, Z 6II, Z 7, Z 7II, Z 8, Z 9, Z f, Z fc, Z50II, Z5II, Z6III.
- **Firmware pseudoTable row**: A `<div class="row">` inside `<div id="firmware" class="contentsType">` → `<div class="pseudoTable">` on a product page. The first row is the latest firmware release.
- **`C:Ver.` prefix**: Nikon's device-class version prefix for cameras (`C:` = camera). The stripper is class-agnostic and strips any `<token>:Ver.` prefix.
- **Model-key normalization**: The alias-set intersection rule — uppercase, strip `Z`-prefix whitespace variants, remove `_` and spaces, compare against normalized forms of each `<product name>`; match on alias-set intersection (display name, no-space form, slug form). Mirrors `panasonic_lumix.py` / `sony_alpha.py`.
- **Authoring contract**: The strict, documented interface (per ADR-0005) every module must implement: `check_firmware(url, model, http_client) -> dict`, plus `MODULE_VERSION` and `SUPPORTED_DEVICE_TYPE` constants.
