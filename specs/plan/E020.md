# Epic Details: E020 — Official Module Health Monitoring

- **Category**: PRODUCT
- **Priority**: P2
- **Source**: {PRD:CAP-014}

## Scope
Implement in-app notification when a shipped official module consistently fails scraping. Track consecutive failure counts for official modules and alert the operator through the UI (and optionally via notification channels) when the threshold is exceeded, signaling that a project update with a fixed module may be needed.

## Traceability & Dependencies
- **Actors**: Operator (receives alert)
- **Key Entities**: Official module health state (consecutive_failures, last_success)
- **Depends on**: E016 (official modules + seeder), E014 (notification dispatch), E015 (activity log)
- **Dependency Contracts**: E016 official modules with is_official flag; E014 NotifierService; E015 ActivityRepository
- **Depended on by**: None
- **Produces (shared)**: Module health monitoring service, health status in UI
- **Constraints**: Only monitors official (is_official=true) modules

## Acceptance Criteria
- [ ] Track consecutive failure count for each official module
- [ ] Configurable failure threshold (default: 5 consecutive failures)
- [ ] In-app notification (UI banner/badge) when threshold exceeded
- [ ] Optional notification dispatch via configured channels
- [ ] Reset failure counter when check succeeds
- [ ] Health status visible on the module card for official modules
- [ ] Tests for failure tracking, threshold, reset logic

## Specify Input
- **Description**: Official module health monitoring — detect consistent scraping failures in shipped modules, alert operator in-app and via notification channels
- **Actors**: Operator
- **Key Entities**: Module health state
- **Depends on Artifacts**: E016 official modules, E014 notifier, E015 activity log
- **Constraints**: Only official modules, configurable threshold
