# Epic Details: E023 — On-Demand Version Search during Device Creation

- **Category**: PRODUCT
- **Priority**: P1
- **Source**: {PRD:CAP-001}

## Scope
Implement on-demand version search for a model using a module during device creation. Add a button next to the Module dropdown on the DeviceForm. Disable it unless a module is selected and Model has a value. When clicked, it queries the backend API to search the latest version using the selected module for the specified model. If successful, sets the Current Version field; if not, displays a clear error.

## Traceability & Dependencies
- **Actors**: Operator
- **Depends on**: E006 (Device Inventory), E007 (Module Engine), E012 (Manual Checks)
- **Dependency Contracts**: E007 loader and E012 checking logic
- **Produces (shared)**: API endpoint `/api/v1/checks/search-version`, DeviceForm UI with version search button
- **Constraints**: Polite scraping client must be used

## Acceptance Criteria
- [ ] Backend route POST `/api/v1/checks/search-version` accepts `module_id` and `model`, loads the module, runs it via `ModuleRunner`, and returns the version.
- [ ] If search fails or returns no version, returns HTTP 400 with details.
- [ ] Form button next to Module dropdown is enabled only when Module is selected and Model is not empty.
- [ ] Clicking the button triggers the version search and sets the "Current Version" field on success.
- [ ] Displays a clear error message below the form on version search failure.
- [ ] Integration tests verify backend version search route success and failure.

## Specify Input
- **Description**: Form button and backend API to search/retrieve version for a module and model before device creation.
- **Actors**: Operator
- **Depends on Artifacts**: E006, E007, E012
- **Constraints**: No database side-effects or notifications during version search.
