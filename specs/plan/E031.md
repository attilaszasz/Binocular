# Epic Details: E031 — Canon Endpoint Discovery Cache

- **Category**: TECHNICAL
- **Priority**: P2
- **Source**: {PRD:CAP-015}{SAD:ADR-0012}{SAD:ADR-0014}

## Scope

Persist source-discovered Canon model-to-firmware endpoint metadata for the camera and lens modules in the existing SQLite database. Fresh mappings allow version search, manual checks, and scheduled checks to make one live firmware request through the existing centralized client; firmware versions are never stored or returned from this cache.

## Traceability & Dependencies

- **Actors**: Canon camera or lens owner; self-hosting operator
- **Key Entities**: CanonFirmwareEndpointMapping, discovery timestamp, refresh lease, firmware endpoint, live firmware result
- **Depends on**: E002, E012, E013, E023, E027, E028, E029
- **Dependency Contracts**: E002 provides forward-only SQLite migrations and WAL access; E012/E013/E023 route manual, scheduled, and version-search checks through the module runner; E027 provides centralized robots, 30-second shared Canon pacing, retry, deadline, and cancellation enforcement; E028/E029 provide Canon discovery flows and fixture matrices.
- **Depended on by**: None
- **Produces (shared)**: Canon endpoint-cache migration and repository, cache lifecycle contract, deterministic fixture/integration suite
- **Constraints**: Persist only exact model identity, catalogue family, firmware action URL, discovery timestamp, and validation metadata; a mapping is fresh only when less than 24 hours old; no authoritative firmware-version cache; every live request uses the centralized client and retains Canon's 30-second shared delay; expired mappings bypass cache; endpoint transport/status/parsing/model-identity failure invalidates then performs one full discovery fallback; recovery failure is visible; no stale success; restart persistence; database-backed same-model single-flight coordination for discovery, refresh, and warm-hit live requests.

## Acceptance Criteria

- [ ] A forward-only idempotent SQLite migration persists Canon endpoint mappings and refresh leases across restart without storing firmware versions; rollback uses the existing pre-migration backup procedure.
- [ ] A mapping is reusable only when younger than 24 hours; at exactly 24 hours it is expired. Version search, a manual check, and a scheduled check issue exactly one live firmware request through the centralized client, while concurrent same-model warm callers coalesce into that request and share its live response. Robots handling and the shared 30-second Canon pacing remain intact, and warm verification completes in 0-30 seconds under injected virtual time.
- [ ] Missing or expired mappings use the complete catalogue → product → firmware flow; cached-endpoint transport, status, parsing, or model-identity failure invalidates the mapping and performs that flow once. If recovery fails, the result is a visible failed check with the last-success timestamp retained; no stale mapping or version is returned.
- [ ] Deterministic captured-fixture tests cover migration, restart persistence, freshness boundary, invalidation, fallback, one-live-request cache hits, concurrent same-model single-flight behavior, camera/lens origin sharing, retries, timeout, cancellation, and all three check entry points without real sleeps or live requests.

## Specify Input

- **Description**: Add a persisted 24-hour Canon firmware endpoint discovery cache for the existing Canon RF Cameras and Canon RF Lenses modules. Cache source-discovered model-to-endpoint metadata only, use a fresh mapping for one live centralized firmware request, and preserve the shared 30-second Canon crawl delay, robots handling, retries, deadlines, and cancellation. Expired mappings must bypass cache. Cached endpoint transport, status, parsing, or model-identity failures must invalidate and fall back once to full catalogue-to-product-to-firmware discovery; recovery failure must be visible and must not return stale data. Cover version search, manual checks, scheduled checks, restart persistence, same-model concurrency, migration safety, deterministic virtual time, and the 0-30 second warm versus 90-120 second cold latency bounds.
- **Actors**: Canon camera or lens owner; self-hosting operator
- **Key Entities**: CanonFirmwareEndpointMapping, refresh lease, firmware endpoint, live firmware result
- **Depends on Artifacts**: E002 migration runner; E012 manual checks; E013 scheduler; E023 version search; E027 centralized pacing; E028/E029 Canon modules and fixtures; ADR-0014
- **Constraints**: Canon Asia English EOS R/RF/RF-S sources only; no firmware-version cache; no raw HTTP; no robots/pacing bypass; 24-hour mapping lifetime; one full discovery fallback; visible failure and preserved last-success state; captured fixtures and injected clocks/sleepers/scripted transport.
