# Epic Details: E038 — Module Catalog Browsing

- **Category**: PRODUCT
- **Priority**: P1
- **Source**: {PRD:CAP-001}{PRD:CAP-012}{PRD:CAP-017}{SAD:ADR-0015}{SAD:ADR-0017}

## Scope
Make each module's discovered catalog browseable/searchable locally, including models not represented in inventory, and provide direct Add to inventory through E037's shared preselected form. Reuse the catalog API, validation, comparison, and delivery behavior rather than introducing a second device-creation or scraping path.

## Traceability & Dependencies
- **Actors**: Operator
- **Key Entities**: Module/capability/controls, CatalogModel/variant, FirmwareObservation/freshness, inventory presence/count, Device
- **Depends on**: E034, E035, E036, E037
- **Dependency Contracts**: E034 bounded local model list/detail/inventory count and explicit refresh/status; E035 working official catalogs; E037 reusable creation form/preselection/query/state hooks; E036 common device validation/reevaluation/deduplication
- **Depended on by**: E039
- **Produces (shared)**: Accessible module catalog browse/search surface, bounded navigation, shared status/source components, direct preselected inventory action and parity integration tests
- **Constraints**: Every browse/search/page operation is local, no unbounded load/render, no installed-from-latest assumption, inventory count is informational not uniqueness validation. Same module-wide controls/capabilities/source guidance and shared creation path as Add Device.

## Acceptance Criteria
- [ ] Each catalog-capable module exposes local paged/searchable discovered models, including unowned ones, with useful display/alias matching and compatibility distinctions, latest known firmware or explicit absence, verification age/status, and relevant source/product/help links. No owned-device filter silently limits source catalog visibility.
- [ ] Each model offers Add to inventory, opening exactly E037's shared form with module and catalog UUID preselected via local detail data. The operator supplies physical-device name and installed firmware/explicit unknown; latest available is never presumed installed. Successful creation uses the identical API validation, comparison, and notification behavior as standard Add Device.
- [ ] Inventory presence/count is visible and updates after creation, but never disables adding another physical device of that model. Integration tests compare both entry points and multiple copies with different installed versions, ensuring independent names/versions/alerts and no duplicated discovery or notification effects.
- [ ] Loading, no discovered models, no matches, stale/paused data, failed/partial refresh, and V1 unsupported-catalog states are explicit and accessible. Existing source guidance/control surfaces remain usable; explicit background Refresh/Retry shows local progress and legacy users retain the labeled manual/per-model route. Browsing itself never starts refresh, even on initial/empty/stale/error views.
- [ ] A 10,000-model fixture proves default-50/max-100 local query/result and rendered windows, bounded pagination/navigation, keyboard/focus/status semantics, and zero manufacturer requests from browsing/searching/typing/selecting/opening the preselected form. Mobile/dark-mode usability and source/request isolation tests pass without rendering or downloading a complete catalog.

## Specify Input
- **Description**: Allow operators to browse/search every module's locally discovered compatible models, including unowned ones, with latest known firmware, verification freshness/status, source guidance/links, and inventory presence/count. Each model's Add to inventory action opens the same device-creation form as standard Add Device with stable module/model preselected and asks for independent name and installed firmware or unknown; do not assume latest is installed or forbid multiple copies. Keep large catalogs bounded and accessible, cover loading/empty/no-match/stale/failed/legacy states and explicit background refresh/retry, and reuse common API validation/comparison/notification behavior. Browsing/search/selection must read local data only.
- **Actors**: Operator
- **Key Entities**: Module, CatalogModel, FirmwareObservation, Device, inventory presence/count
- **Depends on Artifacts**: E034 paged catalog/detail/count and explicit refresh/status APIs; E035 real catalog fixtures; E037 shared preselected form and state/query hooks; E036 common mutation/compare/delivery path
- **Constraints**: Instance-local only; no duplicate creation implementation, manufacturer calls from passive interaction, latest autofill, single-copy restriction, unbounded download/render, or invented legacy catalog support.

## Pipeline Hints
- Test cross-entry-point behavior through the same form/API, not separate mocked creation logic.
