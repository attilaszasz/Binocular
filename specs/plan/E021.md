# Epic Details: E021 — Environment-Based Notification Settings

- **Category**: TECHNICAL
- **Priority**: P1
- **Source**: {PRD:CAP-007}, {PRD:CAP-009}

## Scope
Implement loading and seeding of notification channel (SMTP and Gotify) and authentication configuration settings from container environment variables. At application startup, if these environment variables are present, synchronize them into the database's `notification_channels` table, enabling and configuring them automatically so the web UI, checks scheduler, and NotifierService immediately use them.

## Traceability & Dependencies
- **Actors**: Operator (configures container env vars)
- **Key Entities**: `Settings` model, `notification_channels` table database records
- **Depends on**: E001 (FastAPI app shell), E002 (Database layer), E014 (Notification channels routing/dispatch)
- **Dependency Contracts**: `Settings` class, `NotificationsRepository`, `apprise` notifications config schema
- **Depended on by**: None
- **Produces (shared)**: Settings environment parsing, startup configuration sync/seeding hook
- **Constraints**: Environment variables take precedence at startup; passwords/tokens in the UI remain masked

## Acceptance Criteria
- [ ] Define the following environment configuration fields in the `Settings` class with support for aliases (handling both `BINOCULAR_` prefix and direct/prefixed versions):
  - SMTP: `smtp_host`, `smtp_port` (default: 587), `smtp_use_tls` (default: true), `smtp_username`, `smtp_password`, `smtp_from`, `smtp_to`
  - Gotify: `gotify_url`, `gotify_token`
  - Auth: `basic_auth_enabled` (mapped from `BINOCULAR_AUTH_ENABLED`)
- [ ] Support `_FILE` file-based settings for `GOTIFY_TOKEN` and `SMTP_PASSWORD` secrets.
- [ ] Add a startup seeding hook in `lifespan` (run after migrations) that:
  - If SMTP configuration is defined (i.e. `smtp_host`, `smtp_username`, `smtp_password`, `smtp_from`, and `smtp_to` are set):
    - Upsert the `email` notification channel as `enabled = 1` and store the mapped keys in its config JSON block.
  - If Gotify configuration is defined (i.e. `gotify_url` and `gotify_token` are set):
    - Upsert the `gotify` notification channel as `enabled = 1` and store the mapped keys in its config JSON block.
- [ ] Maintain basic authentication state mapping from `BINOCULAR_AUTH_ENABLED` (handling "true" / "false" case insensitively).
- [ ] Write unit tests to verify:
    - Environment variables are parsed correctly into `Settings`.
    - Secrets file loading works via the `_FILE` pattern.
    - Seeding function correctly inserts/updates rows in `notification_channels` on startup.

## Specify Input
- **Description**: Environment-based notification settings and database seeding at startup
- **Actors**: Operator
- **Key Entities**: Settings model, NotificationsRepository
- **Depends on Artifacts**: E001, E002, E014
- **Constraints**: Standard docker container environment variables, zero-config compatibility
