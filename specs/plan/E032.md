# Epic Details: E032 — Catalog Persistence and Write Ownership

- **Category**: TECHNICAL
- **Priority**: P1
- **Source**: {PRD:CAP-016}{SAD:ADR-0004}{SAD:ADR-0015}{SAD:ADR-0017}{DOD:DDR-003}

## Scope
Introduce the instance-local catalog/observation schema and durable-work primitives while retaining working V1 inventory monitoring. Refactor write ownership coherently before later epics rely on atomic observation/device mutation plus reevaluation; this is not a lock layered over the existing independently committing shared connection.

## Traceability & Dependencies
- **Actors**: Operator, backend maintainers
- **Key Entities**: CatalogModel, model alias/source identifier, compatibility variant, FirmwareObservation, Device, source endpoint mapping, refresh/reevaluation work, NotificationIntent
- **Depends on**: E002, E006, E014, E031
- **Dependency Contracts**: Existing numbered migration runner, fatal pre-migration backup gate, parameterized repositories/WAL pragmas, module-linked inventory, installed/notification history, and Canon endpoint cache. Read existing commit boundaries across all scheduler/check/cache/device/notifier writers before changing them.
- **Depended on by**: E033, E034, E035, E036, E037, E038, E039
- **Produces (shared)**: Stable model/variant and observation mappings; additive schema; explicit legacy/unresolved link state and unknown-installed representation; exact identity resolver; caller-owned write connections/unit-of-work and transaction-aware repositories; generation/cursor/lease and unique delivery-intent persistence primitives
- **Constraints**: SQLite/raw SQL only, append-only numbered migrations, no network during migration or inside write transactions, no new service. Preserve module/device IDs, installed values, history, frequency/pause, source coverage, and existing runtime behavior. Catalog identity is never display-name or inventory-text identity.

## Acceptance Criteria
- [ ] Additive offline migrations apply to empty and populated databases behind the backup gate; preserve device/module identity, installed/notification history, saved intervals/pause, and endpoint metadata. Devices gain nullable catalog linkage for labeled V1/unresolved rows and explicit installed-unknown support; no manufacturer call or invented catalog row occurs during migration.
- [ ] Model UUID is stable across renames and unique within module/source key/canonical compatibility variant. Names/aliases/source IDs/links, region/mount/hardware revision, last-seen status, latest verified firmware/no-firmware/provenance, and separate attempt/last-success metadata persist across restart. Only exact uniquely verified variant matches may link legacy inventory; ambiguity remains visible, missing referenced models are retained, and cross-module links are rejected.
- [ ] Caller-controlled units of work use dedicated write connections with bounded WAL transactions/busy timeout; participating repositories cannot commit independently. All existing write participants use the coherent ownership boundary or explicit writes outside it, with deterministic interleaving/rollback tests proving another writer cannot commit someone else's work. No competing transaction lock is introduced over the shared lifespan connection, and existing V1 checks still work.
- [ ] Durable refresh/reevaluation/delivery primitives support atomic observation or device mutation plus queued local work, bounded cursor/claim state, device revisions/observation generations, and unique device/canonical-version/channel intent identity. Migration, rollback, restart, preserved-history, variant, and concurrency tests pass without enabling unfinished refresh/notification behavior or claiming release readiness.

## Specify Input
- **Description**: Establish a persistent instance-local model catalog separate from physical inventory, preserving firmware compatibility variants and stable source identity. Store names, aliases/source IDs/links, verified firmware observations with provenance/timestamps, independent attempt outcomes, and safe explicit legacy/unresolved associations. Preserve existing inventory, installed values/unknown, delivered history, source controls, endpoint-cache rules, and V1 monitoring through offline additive migration. Replace repository commit ownership coherently across all writers so later shared observations, device changes, bounded reevaluation, and unique notification intents can be atomic without holding transactions over network calls.
- **Actors**: Operator, backend maintainers
- **Key Entities**: CatalogModel, FirmwareObservation, Device revision/link state, refresh/reevaluation work, NotificationIntent/attempt, source mapping
- **Depends on Artifacts**: Existing migration/backup/repository contracts and inventory/notification/cache persistence from E002/E006/E014/E031; ADR-0015 and ADR-0017 entity/ownership boundaries
- **Constraints**: No external DB/broker/cloud or ORM; preserve IDs/controls/history; exact variant-safe linking only; no live source migration; append-only SQL; bounded transactions, centralized HTTP unchanged, all runtime code under backend/src/.

## Pipeline Hints
- No lightweight or checklist-skipping recommendation: schema migration and cross-writer ownership are high-risk prerequisites.
