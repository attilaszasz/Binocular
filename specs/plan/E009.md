# Epic Details: E009 — Module Lifecycle Management

- **Category**: PRODUCT
- **Priority**: P1
- **Source**: {PRD:CAP-003}

## Scope
Implement module lifecycle management through the UI: upload new modules, update existing modules, delete modules. Module files are validated via two-phase validation before being persisted to `/app/modules`.

## Traceability & Dependencies
- **Actors**: Operator, Module Author
- **Key Entities**: Module
- **Depends on**: E007 (module engine + validator), E004 (UI components)
- **Dependency Contracts**: E007 provides ModuleValidator; E004 provides shadcn/ui
- **Depended on by**: E010, E011, E013, E016, E019
- **Produces (shared)**: Module CRUD API routes, ModulesPage UI, ModuleCard, ModuleUploadForm, ModuleStatusBadge
- **Constraints**: File-based module storage under /app/modules

## Acceptance Criteria
- [ ] POST `/api/v1/modules` uploads and validates a module file
- [ ] PUT `/api/v1/modules/{id}` updates an existing module
- [ ] DELETE `/api/v1/modules/{id}` removes a module
- [ ] GET `/api/v1/modules` lists all registered modules
- [ ] Validation errors returned with structured per-phase results
- [ ] Frontend ModulesPage with ModuleCard, ModuleUploadForm, ModuleStatusBadge
- [ ] Tests for upload, update, delete lifecycle

## Specify Input
- **Description**: Module lifecycle management — upload, update, delete modules via UI with two-phase validation
- **Actors**: Operator, Module Author
- **Key Entities**: Module
- **Depends on Artifacts**: E007 module engine, E004 UI components
- **Constraints**: File-based storage, two-phase validation before persist
