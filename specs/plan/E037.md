# Epic Details: E037 — Catalog-Driven Device Creation

- **Category**: PRODUCT
- **Priority**: P1
- **Source**: {PRD:CAP-001}{PRD:CAP-012}{PRD:CAP-016}{SAD:ADR-0015}{SAD:ADR-0017}

## Scope
Replace catalog-capable free-text/live version lookup in Add Device with an accessible searchable model dropdown backed by the local database. Deliver one reusable form that accepts module/model preselection for Modules-page onboarding while preserving independent physical-device name, installed firmware/unknown, source guidance, and the common validation/comparison/delivery path.

## Traceability & Dependencies
- **Actors**: Operator
- **Key Entities**: CatalogModel UUID/variant, ModuleContractDescriptor, Device/name/installed-unknown/revision, FirmwareObservation
- **Depends on**: E032, E033, E034, E035, E036, E004, E030
- **Dependency Contracts**: E034 local paged name/alias list/detail and explicit refresh/status APIs; E035 working official catalogs; E036 stable-ID mutation/unknown/revision payloads and shared reevaluation; existing source/help metadata and accessible SPA primitives
- **Depended on by**: E038, E039
- **Produces (shared)**: Catalog-backed DeviceCreationForm, searchable model combobox/query hooks, module/model preselection interface, installed/unknown validation, mutation/reevaluation hooks, consistent state/source guidance components
- **Constraints**: Opening/typing/selecting/form preselection never invokes modules or manufacturers. Latest is read-only reference, never installed default. Local result/render windows bounded, stable identity saved, multiple physical copies permitted, and V1 fallback labeled rather than silently broken.

## Acceptance Criteria
- [ ] Selecting a source/module enables a DB-backed searchable model combobox matching display names and aliases but saving catalog UUID and module identity. Compatibility distinctions are visible and cross-module/stale-selected identity validation is consistent with the backend. Source guidance, canonical source/product links, and separate consumer-help links remain useful without vendor calls.
- [ ] Shared form always asks for physical-device name and independently entered installed firmware or explicit unknown. Latest known firmware/verified age/status is displayed separately and never autofills installed, including with preselection or async result changes. Unknown/incomparable does not display current; multiple devices may choose the same model.
- [ ] Both normal and preselected form modes handle local loading, empty catalog, no matches, stale/paused observation, failed/partial refresh, and legacy unsupported-catalog states. Explicit background Refresh/Retry shows progress without blocking ordinary local selection; no effect from opening, typing, selecting, or stale/empty data triggers a manufacturer request.
- [ ] The shared form accepts module/model preselection via the local single-model endpoint without loading the entire catalog, preserves expected selection safely, and submits through E036's common validation/mutation/reevaluation. Labeled V1 manual-entry/explicit per-model-check fallback remains available only where supported; ambiguous migrated inventory requires explicit compatible model resolution, not guessing or latest-version fill.
- [ ] Keyboard navigation, active option, labels, Escape, focus/error/status announcements and mobile/dark-mode behavior pass accessibility tests. A 10,000-model fixture proves bounded max-100 local result/render windows and zero manufacturer requests throughout form interaction; creation/repeated-submit tests exercise common deduplication behavior without confusing multiple intentional physical copies with notification duplicates.

## Specify Input
- **Description**: Let operators add owned devices by selecting a module then searching locally discovered compatible model names/aliases in an accessible dropdown. Save stable model identity and independent device name/installed firmware or explicit unknown; latest known firmware is separate reference information, never presumed installed. Preserve source/help links and all loading/empty/no-match/stale/failed/legacy states, with explicit background refresh/retry only. Build one reusable preselectable form for both standard Add Device and upcoming Modules-page direct creation, using the same backend validation, local comparison, and notification path with bounded local queries/rendering and no manufacturer traffic on opening/typing/selection.
- **Actors**: Operator
- **Key Entities**: Module, CatalogModel, Device, FirmwareObservation, installed-unknown state
- **Depends on Artifacts**: E034 catalog list/detail/refresh/status APIs, E035 official catalog fixtures, E036 device mutation/reevaluation API, source guidance and SPA primitives, E033 V1 capability/fallback behavior
- **Constraints**: No live search endpoint for catalog UI, no latest autofill, explicit unknown not current, stable compatible IDs, accessible bounded combobox, same form supports preselected module/model, intentional multiple physical devices allowed.
