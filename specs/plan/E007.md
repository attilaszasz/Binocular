# Epic Details: E007 — Module Engine & Contract

- **Category**: TECHNICAL
- **Priority**: P1
- **Source**: {PRD:CAP-002}{SAD:ADR-0005}

## Scope
Implement the extension module engine: authoring contract definition, importlib-based loader, per-invocation runner with asyncio.wait_for timeout and Exception+SystemExit error boundary, and two-phase validation (static AST + optional runtime proof). Modules execute unsandboxed, in-process.

## Traceability & Dependencies
- **Actors**: Module Author (indirect)
- **Key Entities**: Module (name, device_type, version, author, file_path, is_official), ModuleContract, ValidationResult
- **Depends on**: E002 (DB + migrations), E005 (ScrapeClient injection)
- **Dependency Contracts**: E002 provides RepositoryBase; E005 provides ScrapeClient
- **Depended on by**: E009, E010, E011, E016, E019
- **Produces (shared)**: ModuleContract interface, ModuleLoader, ModuleRunner, ModuleValidator, extensions package
- **Constraints**: unsandboxed, importlib, asyncio.wait_for, two-phase validation

## Acceptance Criteria
- [ ] `backend/src/binocular/extensions/contract.py` defines the module authoring contract
- [ ] Loader discovers and loads .py modules from the modules directory
- [ ] Runner executes module with ScrapeClient injection and asyncio.wait_for timeout
- [ ] Error boundary catches Exception + SystemExit per invocation
- [ ] Two-phase validation: AST static checks + optional runtime proof
- [ ] Validation errors include AI-friendly structured output
- [ ] Module migration creates `modules` table
- [ ] Tests for loader, runner, validator with valid/invalid modules

## Specify Input
- **Description**: Extension module engine with authoring contract, importlib loader, error-bounded runner, two-phase validation
- **Actors**: Module Author
- **Key Entities**: Module, ModuleContract, ValidationResult
- **Depends on Artifacts**: E002 DB layer, E005 ScrapeClient
- **Constraints**: Unsandboxed, in-process, timeout via asyncio.wait_for
