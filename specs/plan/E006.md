# Epic Details: E006 — Device Inventory Management

- **Category**: PRODUCT
- **Priority**: P1
- **Source**: {PRD:CAP-001}{SAD:ADR-0009}

## Scope
Implement device inventory CRUD with devices linked to modules from the start (module-derived device type, no standalone DeviceType entity). Includes stored firmware versions, one-click update confirmation, and the inventory API + frontend page with DeviceCard, StatCard, DeviceForm.

## Traceability & Dependencies
- **Actors**: Operator
- **Key Entities**: Device (name, model, current_version, module_id FK, last_checked, has_update, last_notified_version)
- **Depends on**: E002 (DB + migrations), E004 (UI primitives)
- **Dependency Contracts**: E002 must provide RepositoryBase and migration runner; E004 must provide shadcn/ui components
- **Depended on by**: E010, E012, E014
- **Produces (shared)**: Device entity, InventoryRepository, InventoryService, inventory API routes, InventoryPage UI
- **Constraints**: module_id FK to modules table; device type derived from module

## Acceptance Criteria
- [ ] Device migration creates `devices` table with module_id FK
- [ ] CRUD API: POST/GET/PUT/DELETE `/api/v1/devices`
- [ ] One-click update confirmation endpoint (PUT `/api/v1/devices/{id}/confirm`)
- [ ] Frontend InventoryPage with DeviceCard, StatCard, DeviceForm
- [ ] Module selection in DeviceForm
- [ ] Device type displayed from linked module's `device_type` field
- [ ] Tests for repository, service, and API layer
