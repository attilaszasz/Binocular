# Epic Details: E010 — Update Detection & Comparison

- **Category**: PRODUCT
- **Priority**: P1
- **Source**: {PRD:CAP-006}

## Scope
Implement the core update detection and version comparison service. Runs a module against a device's firmware source, parses the returned version, and compares it against the device's stored current version to determine if an update is available. Defines the CheckResult event shape consumed by downstream epics.

## Traceability & Dependencies
- **Actors**: None (internal service)
- **Key Entities**: CheckResult (device_id, module_id, latest_version, current_version, has_update, checked_at, success, error_message)
- **Depends on**: E006 (Device entity), E007 (Module engine), E005 (ScrapeClient)
- **Dependency Contracts**: E006 Device entity; E007 ModuleRunner; E005 ScrapeClient
- **Depended on by**: E012, E013, E014, E015
- **Produces (shared)**: CheckService, VersionCompare utility, CheckResult event shape
- **Constraints**: Must handle version strings from diverse manufacturers

## Acceptance Criteria
- [ ] `backend/src/binocular/services/checks.py` orchestrates module → compare → result
- [ ] `backend/src/binocular/services/version_compare.py` handles diverse version formats
- [ ] CheckResult captures device_id, latest_version, current_version, has_update, timestamps
- [ ] Device.has_update and Device.latest_version updated after each check
- [ ] Error cases (module failure, scrape failure) produce failed CheckResult with error_message
- [ ] Tests with mock module returns and edge-case version strings

## Specify Input
- **Description**: Update detection and version comparison — run module, compare versions, produce CheckResult events
- **Actors**: None
- **Key Entities**: CheckResult
- **Depends on Artifacts**: E006 Device, E007 Module engine, E005 ScrapeClient
- **Constraints**: Version comparison must handle diverse manufacturer formats
