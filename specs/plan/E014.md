# Epic Details: E014 — Notification & Alerting

- **Category**: PRODUCT
- **Priority**: P1
- **Source**: {PRD:CAP-007}{SAD:ADR-0007}

## Scope
Implement notification dispatch via Apprise with Email/SMTP and Gotify channels. Includes responsive HTML email rendering via Jinja2 templates (light-themed, mobile-friendly), notification deduplication via last_notified_version tracking per device, notification channel configuration via UI, and delivery failure logging.

## Traceability & Dependencies
- **Actors**: Operator (configures channels)
- **Key Entities**: NotificationChannel (type, config), Device.last_notified_version
- **Depends on**: E010 (CheckResult), E008 (secrets for SMTP/Gotify), E006 (Device entity)
- **Dependency Contracts**: E010 CheckResult event; E008 _FILE secret loader; E006 Device entity
- **Depended on by**: E020 (official module health notifications)
- **Produces (shared)**: NotifierService, EmailRenderer, notification API routes, SettingsPage UI
- **Constraints**: Apprise, Jinja2 templates, deduplication

## Acceptance Criteria
- [ ] Notification channel migration creates `notification_channels` table
- [ ] Device.last_notified_version column added to devices table
- [ ] Apprise dispatches via Email/SMTP and Gotify
- [ ] HTML email rendered via Jinja2 with light theme and mobile-friendly layout
- [ ] Deduplication: no duplicate notification for same version; re-notification only when version > last_notified_version
- [ ] Channel configuration via API and SettingsPage UI
- [ ] Test notification endpoint for validating channel config
- [ ] Delivery failures logged in activity log
- [ ] Tests for deduplication logic, email rendering, dispatch
